# 内容运营助手

当前版本提供中文桌面工作台，可选择视频、预览与生成封面、管理抖音、微信视频号和小红书账号、执行平台对应任务并回查结果。视频号受保护的测试素材草稿闭环已实机通过，验证范围见下方记录；小红书本人登录、真实鉴权与账号查询已验证，独立环境中的测试草稿已完成故障后的受限补全、单次暂存及只读恢复保留核验；全新任务从上传到核验的一次性流程仍待单独复验，普通执行入口保持关闭，原环境草稿保留原样。发布引擎复用 [MatrixMedia v0.13.3](https://github.com/hanliang97/MatrixMedia/tree/v0.13.3)，源码保留在 `engine/MatrixMedia`；本项目及修改遵循 GPL-2.0-only。

抖音默认保存草稿、仅自己可见；视频号草稿尚未对外发布，正式发布可见范围未验证。登录和平台本人验证仍需本人完成；日常任务通过程序执行。桌面界面已经接入真实任务记录。

## 按人员批量准备草稿（0.4.0）

1. 打开 **人员与账号**，先连接平台账号，再创建人员；每个人在每个平台选择一个账号。已有账号不会自动分配给任何人，同一账号也不能同时绑定两个人。
2. 回到 **发布工作台 → 按人员·多平台**，选择人员，自动带出其绑定的账号。可取消本次不需要的平台，共用视频、标题、简介和封面。
3. 点击 **生成封面并准备任务**，再点击 **执行批量草稿**；确认窗口会列出人员、具体账号、实际执行项和待验收项。程序按平台顺序执行，不同时启动多个上传引擎。
4. 在 **任务记录** 查看同一批次的各平台结果。结果不明先回查；停止后如有未开始的平台，可再次确认后继续，已开始的平台不会重跑。改名、改绑或素材变化会使旧批次失效。

这一阶段仅做批量草稿：抖音、视频号沿用已开放的草稿能力，小红书仍等待全新任务完整复验，批次不会执行该平台。正式多平台发布尚未开放；原有**单平台**入口继续保留。包含小红书时共用标题最多20字，超限时提示修改，不自动截断。

人员表、批次和子任务位于被Git忽略的`.local/`，只留在本机；本次没有向GitHub上传人员、任务或素材。新增能力通过合成素材与模拟引擎离线验收，未操作真实平台账号或草稿。

## 内容定位与AI接口

在“人员与账号”的“内容定位”中选择人员。没有平台账号也可建档：填写行业业务、产品服务、运营目标，目标客户和优势限制可选，点击“保存基础资料”。保存不会发送AI请求。先预览本次分析材料，再选择已配置的服务生成画像建议，修改后点击“确认采用这版画像”。新分析失败或停止不会覆盖原确认版本。

在“系统状态 → AI接口设置”可分别填写OpenAI、Claude和DeepSeek的接口地址、文字模型与密钥。三项初始均无凭据，程序不会读取环境中已有的图片生成密钥，不会自动测试连接。Claude使用Messages协议，OpenAI和DeepSeek使用Chat Completions协议；支持HTTPS及本机回环HTTP地址。密钥通过系统加密存储，留空可沿用该配置已保存的密钥，更换地址时需重新填写。

具体填写与操作步骤见[AI接口与定位使用说明](docs/ai-setup.md)。

“分析已有账号”已接入样本选择、范围展示与材料预览流程，但三平台真实采集仍关闭：现有读取代码尚未核实作品响应与本人身份的归属证据，小红书有界分页核心通过离线夹具验证，不能据此称为实机可用。当前可先用自主填写流程；不会以空数据或固定文案冒充账号分析结果。

本轮画像分析和三家接口仅用合成客户、模拟加密和模拟响应验证，未使用真实密钥或向AI发送真实客户资料。配置完成后，点击分析会把预览材料发往所选AI服务。画像、样本、接口配置位于被Git忽略的`.local/`，不进入源码包或应用包。0.6.0 同步画像、登录、账号移除和易用性改进，并增加 Windows 安装构建。

## 桌面使用

本机易用性改进：

- 发布工作台可直接打开“人员绑定”，保存后立即更新人员与账号选择；基础资料加载不再等待账号采样能力检查。
- “单平台发布 / 草稿”中，抖音直接选择保存草稿、私密发布或公开发布；多平台入口明确只保存草稿。视频号正式发布、小红书执行限制继续保留。
- 视频选择区域支持拖入一个本机视频，也可点击选择。拖入只更新素材，仍需准备、检查和确认执行。
- 同平台可分别保存多个账号登录，选择账号执行时无需退出其他账号；上传任务依次执行。账号主名称须不同，不要只更改连字符后的备注；平台要求的本人验证仍需完成。
- 任务记录可按最近操作日期筛选（执行、回查，尚未执行按创建）。删除记录是移到可恢复的本机回收站，不会删除平台作品、素材、草稿或执行证据；回收站中的任务不能继续执行，恢复后原执行状态不变。
- 每次回查生成并保存本机报告，完成后自动展示；报告分别列出草稿/作品、可见范围和审核的已知与未知信息，并提供下一步建议。旧任务不会凭空补写历史报告，可再次回查后生成。

双击桌面上的“内容运营助手”，或项目内的 `dist/内容运营助手.app`，无需输入命令。

1. **账号管理**：刷新已有账号，或选择平台、填写本机账号名称后扫码连接。视频号使用微信完成本人登录。
2. **发布工作台**：先选平台，再选择对应账号和视频，填写标题和简介。封面可自动生成，也可选择图片。
3. 点击 **生成封面并准备任务**，检查右侧封面预览，再点击 **执行任务：保存到抖音草稿**。
4. 也可以在 **任务记录** 中找到待执行任务，直接点击右侧的 **执行任务**；这里还可查看状态、核验截图或点击 **回查结果**。已执行任务不能重复提交。
5. 需要实际发布时，选择 **实际发布** 和可见范围；系统会再次显示账号、标题与范围供确认。

抖音草稿流程已实机验证；真实发布的新作品验收仍待单独完成。视频号已通过本人连接、测试素材上传、自选封面、保存、独立恢复核验及原样保留；完整手机二维码扫码未单独验收，真实发表与可见范围尚未开放。

Mac 本机应用：内置 Node 运行时，仍引用项目目录中的执行引擎和任务数据。请保留原项目文件夹；此 Mac 包仍依赖原目录；Windows 安装版使用独立的程序和用户数据目录。关窗口会隐藏应用；有操作执行时退出会提示并停止后台流程。

新账号扫码完成后会登记到本机账号列表，并回读登录状态。同平台账号名请使用不同的主要前缀；不同平台允许使用相同名称：`品牌-A` 和 `品牌-B` 在现有引擎中会共用登录位置，新建时系统会拦截这类冲突。停止操作会取消后续提交并清理当前引擎；重开后的中断任务显示“待核实”，可回查且不能重发。

抖音扫码图必须解码并核实为登录码后才展示，页面背景、Logo和推广二维码不会作为登录图。首次获取取决于平台页面加载；尚未取得有效二维码时显示等待提示。桌面连接抖音时会自动打开官方登录窗口，扫码后如果平台要求短信等本人验证，应在该窗口由本人完成；应用不自动填写手机号、验证码或勾选协议。扫码及本人验证完成、引擎确认会话后显示“正在确认登录状态，无需重复扫码”，只核对本次平台与账号，保留其他平台缓存，避免无关平台检查拖慢这次登录。不从二维码出现或仅手机确认推断电脑端已登录。

抖音内置登录组件出现分包加载失败（空白登录区）时，在二维码出现前绕过资源缓存重新加载一次；再次失败会结束等待并提示检查网络。恢复共用原登录期限，不清除 Cookie、账号资料或草稿，二维码已显示后不自动重载打断扫码。

在“人员与账号 → 已添加的账号”点击对应行的“移除账号”，确认后退出该账号在此应用中的登录并移除本机登记。已绑定人员时，需先将该人员对应平台改为“暂不绑定”并保存；后台操作期间不能移除。尚未执行的旧任务会标记“已作废”，重新连接同名账号后也需重新准备。历史任务、画像、素材和草稿存储保留，手机及日常浏览器的登录不受影响。共享或异常登录分区、独立浏览器模式会被拦截，不会为了移除而清空整个浏览器分区。

## 命令接口与开发

在项目目录执行，开发执行器支持 macOS / Linux / Windows。Mac/Linux 需要 ffmpeg、ffprobe、Python 3；Windows 使用自带原生保护程序，媒体工具可设置绝对路径。引擎安装与构建必须使用 Node 20.x。

```sh
node bin/content-ops.mjs doctor
node bin/content-ops.mjs accounts
node bin/content-ops.mjs prepare --input examples/douyin-job.json
node bin/content-ops.mjs run <准备结果中的任务编号>
node bin/content-ops.mjs verify <任务编号>
node bin/content-ops.mjs show <任务编号>
```

把示例文件的视频路径、账号分组和文案改成实际值。也可用 `prepare --phone 分组 --video 视频路径 --title 标题`；没有 `--cover` 时，从视频前段抽帧，生成 900×1200 的竖封面，保留完整画面并填充边缘。这是流程用封面，正式内容可传入自己设计的图片。

`mode` 可选 `draft`、`publish`；`visibility` 可选 `private`、`friends`、`public`。实际发布使用独立任务，明确设定 `mode: publish`，覆盖引擎账号的“默认草稿”，不修改账号偏好。新增平台只允许 `mode: draft`，使用 `platform: sph`、`visibility: unknown`；不要传抖音的可见范围。视频号工作台标题会放在平台视频描述开头，短标题可留空，填写时为 6～16 字且无特殊标点。

按已知作品编号只读查询：

```sh
node bin/content-ops.mjs works --phone 账号分组 --work-id 作品编号
```

作品存在、可见范围已确认、审核通过是三件事。未知字段会保留为未知，不能从“接口返回成功”推断审核通过。

## 任务记录

任务及日志保存在被 Git 忽略的 `.local/`。每个任务保存视频和封面的 SHA-256；执行前文件变化会被拦截。任务开始前持锁并写入 `running`，之后相同任务编号不能再次上传。

`draft_confirmed` 表示已恢复并核实草稿，`confirmed` 表示作品集合、内容、时间和可见范围匹配，`unknown` 表示需要回查。账号由系统文件锁保护，并持久保存子进程组占用信息。包装进程意外退出而引擎仍活着时，新任务会被阻止。进程中断、超时或平台结果不明确时不会自动重发；作品的 `verify` 仅查询；抖音和视频号草稿核验会恢复并在必要时原样暂存，以保留下次“继续编辑”入口；小红书核验路径只读恢复，并在关闭恢复页后独立回读确认保留，不重新上传视频或发布作品。平台列表更新可能延迟，稍后可再次回查。

抖音回查若已唯一匹配本次新作品，会先保存作品编号；后续可见范围查询失败也保留这份创建证据。此时详情会说明“作品已创建，范围仍待核实”，任务继续保持待核实且不能重发，不把创建成功当成公开可见或审核通过。发布前作品列表不完整时仍阻止上传，并显示已识别的查询失败原因。

封面、任务记录和引擎日志可能包含本地素材信息，请保留在本机。登录态继续由 MatrixMedia 管理，本项目不复制 Cookie。避免同时启动 MatrixMedia 图形应用与本项目的执行命令。

```sh
git submodule update --init
```
