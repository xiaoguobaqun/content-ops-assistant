# Windows 适配交接：以 v0.4.0 为基线

这是一份供 Windows 电脑上的开发者或 Codex 继续工作的交接说明。仓库目前提供 Mac 本机版本的净化源码，**不是已经可以运行的 Windows 版**。请先完整阅读 README、本文件和 `src/platforms.mjs`，再适配；不要仅修改打包目标便宣称支持 Windows。

## 当前功能与边界

桌面使用 Electron、HTML/CSS/JavaScript，保留发布工作台、任务记录、人员与账号、系统状态四页。发布引擎为 MatrixMedia v0.13.3 加本项目修改，已经作为普通源码目录包含在 `engine/MatrixMedia`，不需要拉取子模块或额外的引擎仓库。

0.4.0 新增按人员操作：每个人每个平台最多绑定一个账号，同一账号只能归属一个人。选人后带出其绑定平台，共用视频、标题、简介和封面，一次原生确认后顺序保存草稿；每个平台保留独立任务与结果。批次位于 `.local/batches`，人员表为 `.local/people.json`，子任务位于 `.local/jobs`。这些目录不会随仓库提供，首次启动应为空，不得把缺少私有资料当成源码不全。

| 平台 | 当前允许的操作 | 尚未完成 |
| --- | --- | --- |
| 抖音 | 已有草稿流程；保留原单平台发布入口 | 真实新作品正式发布的完整实机验收 |
| 微信视频号 | 测试素材草稿保存、独立恢复核验及原样保留 | 正式发表和可见范围验收 |
| 小红书 | 本人登录及账号查询；草稿可离线准备与查看 | 草稿实机验收，`executionEnabled:false`；正式发布 |

人员批次只允许草稿，小红书不得因 Windows 适配解除执行限制。Mac 上既有平台验证不等于 Windows 实机验证；不能把上传成功、点击按钮、页面跳转或任务返回直接判断为成功。

## 建议先阅读的模块

- `src/people.mjs`：人员、账号归属、修订号和快照检查。
- `src/batches.mjs`、`src/batch-guard.mjs`：批次准备、摘要、原生确认范围、顺序执行和中断恢复。
- `src/jobs.mjs`：单任务指纹、先落盘再上传、未知结果和独立回查。
- `src/local-store.mjs`、`src/lock.mjs`、`src/process.mjs`：元数据锁、引擎锁、子进程占用与取消；是 Windows 适配的重点。
- `desktop/service-core.mjs`、`desktop/main.cjs`、`desktop/ipc-policy.cjs`：后台活动、文件选择权限和原生发布/批次确认。
- `desktop/ui/app.mjs`、`desktop/ui/people-ui.mjs`：现有单平台与人员入口；优先复用，不重做界面。

## 已知 Windows 障碍

| 位置 | 当前实现 | 适配要求 |
| --- | --- | --- |
| `src/lock.mjs`、`src/local-store.mjs` | 通过 Python `fcntl.flock` 持有文件描述符；引擎锁会检查旧进程占用 | 提供真正的 Windows 跨进程互斥，含崩溃释放与后台子进程仍存活时的保护；不能改成只检测一个文件是否存在 |
| `src/process.mjs` | 明确拒绝 win32，使用负 PID、POSIX 进程组和 `ps` | 实现 Windows 进程树生命周期，取消和超时须停止全部后代并核实；父进程退出不代表引擎已停止 |
| `src/engine.mjs` | doctor 检查 Python/fcntl；已有 electron.exe 路径不代表整条链路可用 | 同步适配环境检查、可执行文件解析与进程保护，维持现有 CLI 契约 |
| `desktop/worker-client.cjs` | PATH 使用 Mac 常见目录和冒号分隔 | 用系统路径分隔符和 Windows 可用程序位置，避免破坏系统环境 |
| `desktop/main.cjs` | 默认 Node 指向本机 darwin-arm64 工具链 | 明确解析 Windows Node/Electron 运行时和用户目录，不硬编码他人电脑路径 |
| `scripts/start-desktop.mjs`、`scripts/build-desktop.mjs` | 直接使用 Electron.app、Mac Node、PlistBuddy、iconutil、codesign | 新增可重复的 Windows 开发启动与安装包构建；保留 Mac 构建能力 |
| `scripts/build-engine.mjs` | 要求 Node 20，但调用的 runProcess 目前拒绝 Windows | 先打通受保护的 Windows 进程调用，再构建；不能只删版本或平台校验 |
| `test/`、`scripts/run-tests.mjs` | Node 20、Chrome 和部分 ffmpeg 路径带有 Mac 假定 | 参数化工具路径；对 Windows 提供等价行为测试，不把防重复或停止测试直接跳过 |

WSL 可以辅助阅读或部分测试，但 WSL 下通过测试不能代替原生 Windows 桌面、文件选择、浏览器窗口、停止操作和安装包验证。

## 必须保留的任务保护

1. 准备任务保存视频、封面及内容的 SHA-256；执行前再次检查，不自动替换素材、人员或账号。
2. 上传前持锁并保存运行状态。相同任务一旦开始，未知、超时或中断均不自动重发。
3. 批次确认绑定持久化摘要、尝试编号和本次尚未开始的目标集合，渲染层不能扩大范围。批次子任务不能从单平台入口或 CLI 绕过父任务独立执行。
4. 遇到未知或取消停止后续平台；重开不自动续跑。只允许另行确认继续从未开始的子任务，已成功和待核实项不能重跑。
5. 批次结果按子任务事实恢复。父记录尚未更新而子任务已开始时，不能把它当成新任务；待验收平台不计为成功。
6. 保留两个互斥层次：短时间元数据写入锁与执行引擎锁。锁竞争需能等待，批次收尾要可靠落盘，不能嵌套取得同一引擎锁造成死锁。
7. 作品创建、可见范围及平台审核分别记录；证据不足保留未知。独立回查不能重新上传或发表作品。
8. 平台登录和本人验证由用户完成；新电脑重新登录，不导出、复制或从仓库寻找 Cookie。

## 推荐验证顺序

先在 Windows 本地建立独立开发分支，确认 Node 20、Git、ffmpeg/ffprobe、Chrome 及引擎依赖，再依次打通进程与锁、环境检查、开发启动、离线测试和安装包。依赖准备通常包括进入 `engine/MatrixMedia` 后执行 `yarn install --frozen-lockfile`；现有 Mac 启动和打包脚本需要适配后再运行。

优先使用临时目录、合成视频和模拟引擎。验证人员绑定、跨平台同名账号隔离、重复点击、跨进程锁竞争、取消、引擎遗留进程、素材变化、父子记录不同写入点中断和仅继续未开始项。保留原有 Mac 行为；当前 Mac 基线为79项根测试通过，此数字不代表 Windows 已通过。

离线验收和 Windows 安装包完成后，先使用空白测试账号及测试素材做草稿验证。真实平台登录、已有草稿修改，以及实际公开/私密作品发布，都需要用户另行明确具体账号、内容和范围；本次代码同步没有授权执行这些操作。
